# Instagram Import Studio

Локальная студия для импорта публикаций Instagram и собственных медиа, подготовки промптов и запуска image/video workflow в RunningHub. Приложение работает в браузере, а исходные файлы, настройки, очередь и результаты хранит на компьютере пользователя.

## Возможности

- импорт фото, каруселей и Reels через Apify;
- загрузка локальных изображений и видео;
- повторное использование уже скачанных материалов без лишних запросов к Apify;
- генерация и ручное редактирование промптов через Ollama Cloud или локальный Ollama;
- отдельные пресеты Ollama и RunningHub;
- привязка входов Studio к узлам ComfyUI workflow;
- постоянная локальная очередь генерации с изменением порядка и отменой заданий;
- восстановление очереди после перезагрузки страницы или перезапуска сервера;
- сохранение изображений, видео и превью в локальную папку `output/`.

## Быстрая установка

Создайте пустую папку, скопируйте в неё один установщик для своей системы и запустите двойным кликом:

| Система | Установщик |
| --- | --- |
| Windows | `instal.bat` |
| macOS | `instal.command` |

Установщик при необходимости устанавливает Git и Node.js LTS, скачивает последний стабильный релиз `vX.Y.Z`, выполняет `npm ci` и открывает <http://localhost:5173>. Windows использует `winget`, macOS — Homebrew. Во время установки система может запросить права администратора.

Не закрывайте окно терминала во время работы: вместе с ним остановится локальный сервер.

## Запуск

После установки запускайте приложение двойным кликом:

| Система | Лаунчер |
| --- | --- |
| Windows | `start.bat` |
| macOS | `start.command` |

Если папки `node_modules/` ещё нет, лаунчер установит зависимости. Перед стартом он освободит только порты приложения `4317` и `5173`, затем откроет интерфейс по адресу <http://localhost:5173>.

Если Node.js или npm не найден, установите актуальную LTS-версию с [nodejs.org](https://nodejs.org/) и повторите запуск.

## Обновление

Для установленной стабильной версии используйте:

| Система | Обновление |
| --- | --- |
| Windows | `update.bat` |
| macOS | `update.command` |

Обновлятор скачивает последний опубликованный тег `vX.Y.Z`, устанавливает точные зависимости через `npm ci` и запускает приложение. Если в отслеживаемых Git-файлах есть локальные изменения, обновление остановится до их замены.

Разработчики, работающие с веткой, могут обновиться из терминала командой `./update.sh`: она выполняет `git pull --ff-only`, `npm install` и запускает текущую ветку. Это отличается от `.command`/`.bat`, которые переключаются на последний стабильный релиз.

## Настройка интеграций

Откройте вкладку `Настройки` и добавьте нужные подключения:

- токен Apify для импорта Instagram;
- API-ключ Ollama Cloud или адрес локального Ollama;
- API-ключ RunningHub;
- пресеты моделей и workflow;
- режим RunningHub (`Standard` или `Plus`);
- Node ID, имя поля и Studio ID для каждого входа workflow.

Соответствие Studio ID:

| Studio ID | Данные |
| --- | --- |
| `1` | исходное изображение |
| `2` | промпт выбранного изображения |
| `3` | исходное видео |
| `4` | сгенерированное изображение |
| `5` | промпт выбранного видео |

Промпты изображений и видео сохраняются в задании независимо. Workflow с ID `2` и `5` получает два разных значения.

ComfyUI workflow должен содержать подключённый к финальному результату узел сохранения. Preview-only узлы не публикуют файлы через RunningHub API, поэтому приложение не сможет скачать такой результат.

## Работа с медиа

1. Вставьте ссылку на фото, карусель или Reel во вкладке `Студия` либо нажмите **Загрузить медиа**.
2. Для Instagram приложение запускает `apify/instagram-scraper` с одной ссылкой и лимитом результата `1`.
3. Фото, элементы карусели и Reel сохраняются в `input/`; для Reel локально создаётся превью первого кадра.
4. Подписи, комментарии, профиль и прочие необязательные поля ответа Apify отбрасываются.

Обычный повторный импорт использует исправные локальные файлы. Кнопка **Обновить заново** принудительно скачивает публикацию ещё раз.

Клик по карточке меняет активное превью, а кнопка `Use` добавляет материал во входы генерации. Видео Reel и его первый кадр остаются отдельными материалами.

**Сброс** очищает текущую сессию, превью, метаданные и промпты, но не удаляет файлы из `input/` и `output/` и не меняет постоянные настройки Generation workspace.

## Промпты и генерация

`Generate prompt` отправляет выбранное изображение в действие Ollama, указанное текущим пресетом. Полученный текст можно редактировать, отменять изменения, сбрасывать и сохранять вручную; актуальное значение также автоматически записывается в локальную сессию.

Generation workspace хранит варианты префикса в формате `Название;Текст`, по одному на строку. При выборе варианта итоговый промпт формируется как `Текст, Image`; при выборе **Не выбрано** используется исходный промпт Ollama.

`Image generation` и `Video generation` создают отдельное задание на каждый запрошенный результат. Вкладка `Queue` показывает зафиксированные медиа и промпты каждого задания, выполняет задания последовательно, позволяет менять порядок ожидающих задач и отменять активные или ожидающие задачи.

Очередь и активные RunningHub task ID переживают перезагрузку. Готовые результаты сразу появляются в `Generated Media` и сохраняются в:

```text
output/YYYYMMDD/
```

## Локальные данные и безопасность

Сырые API-ключи не возвращаются из локального API в браузер: интерфейс показывает только маску. Для замены ключа используется **Вставить ключ**, для удаления — **Очистить**.

Подключения сохраняются только локально:

```text
data/connections.local.json
```

На macOS и Linux файл создаётся с правами владельца `0600`. Каталоги `data/`, `input/`, `output/`, файлы `.env*`, `*.local.*`, ключи и сертификаты исключены из Git. Внутренние планы, спецификации и служебные файлы агентов также не входят в репозиторий.

Локальное хранение не отменяет передачу необходимых данных выбранным внешним сервисам: Apify получает URL и токен, Ollama Cloud — выбранные входы и инструкции, RunningHub — workflow-входы и ключ. Эти данные не отправляются в GitHub самим приложением.

Перед каждым коммитом хук проверяет staged-файлы, все отслеживаемые файлы и новые неигнорируемые файлы. Проверка ищет приватные пути, распространённые сигнатуры credentials и точные значения API-ключей из локального `connections.local.json`:

```bash
npm run check:secrets
```

## Разработка

Требования: Git, актуальные Node.js LTS и npm. Для локальной генерации промптов также нужен Ollama.

```bash
npm install
npm run dev
```

`npm run dev` запускает Vite и Express API одновременно и подключает локальный pre-commit hook из `.githooks/`. Клиент доступен на <http://localhost:5173>, API использует порт `4317`.

Основные команды:

```bash
npm test                # тесты Vitest
npm run build           # TypeScript + production-сборка Vite
npm run check:secrets   # аудит секретов и приватных файлов
npm run check           # аудит секретов, тесты и сборка
./start.sh              # зависимости, локальный Ollama и запуск (macOS/Linux)
```

Структура проекта:

- `src/` — React/Vite клиент;
- `server/` — Express API, импорт, интеграции и локальное хранилище;
- `scripts/` — установка зависимостей, обслуживание портов и проверки;
- `.githooks/` — Git hooks проекта.

Runtime-данные, медиа, сборка, внутренние документы и секреты не должны добавляться в Git. Перед публикацией запускайте `npm run check`.
